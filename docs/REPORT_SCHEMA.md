# VibeSift Audit Report Schema & Scoring Specification

This document specifies the normalized data contract for website audit reports generated by VibeSift, detailing the check registry, finding structures, Indian DPDP Act 2023 compliance, and the multi-pillar Launch Readiness Score formula.

---

## 2. Multi-Pillar Launch Readiness Score Formula

The **Launch Readiness Score** measures real-world website health on a 0–100 scale by synthesizing genuine Google Lighthouse engine scores with Python security and privacy evaluations.

### Weighted Pillar Calculation
When live Google Lighthouse metrics are available, the readiness score is calculated as a multi-pillar weighted composite:

$$\text{ReadinessScore} = \sum (\text{CategoryScore}_i \times \text{Weight}_i)$$

| Category Pillar | Weight | Primary Data Source |
| :--- | :--- | :--- |
| **Security** | **25%** | Python DeepAuditor (TLS, HSTS, CSP, framing, CORS, SQLi/XSS resilience) |
| **Performance** | **20%** | Google Lighthouse Performance (`rawLighthouse.categories.performance.score * 100`) |
| **Accessibility** | **15%** | Google Lighthouse Accessibility (`rawLighthouse.categories.accessibility.score * 100`) |
| **SEO & Crawl** | **15%** | Google Lighthouse SEO (`rawLighthouse.categories.seo.score * 100`) + Python BasicAuditor |
| **Privacy & DPDP** | **15%** | Python PrivacyAuditor (15 Indian DPDP Act 2023 compliance checks) |
| **Completeness** | **5%** | Python BasicAuditor (Header, footer, contact, privacy policy, legal routes) |
| **Trust & Legal** | **5%** | Python BasicAuditor (Terms of service, SSL issuer reputation, branding) |

### Critical Security Blocker Rule
If any **Critical** severity finding exists (`counts.critical > 0`), the Launch Readiness Score is strictly capped at **50**:

$$\text{FinalScore} = \min\left(50, \text{ReadinessScore}\right)$$

*Rationale:* A website cannot be marked launch-ready if it suffers from severe unpatched vulnerabilities (such as active SQL injection, cleartext password transmission, or exposed AWS secret keys).

## 3. Lighthouse Category Score Ingestion

Unlike legacy deduction-only systems that penalize minor recommendations with severe score drops, VibeSift directly ingests Lighthouse's calibrated category scores:
* `categoryScores.performance` = $\text{round}(\text{rawLighthouse.categories.performance.score} \times 100)$
* `categoryScores.accessibility` = $\text{round}(\text{rawLighthouse.categories.accessibility.score} \times 100)$
* `categoryScores['best-practices']` = $\text{round}(\text{rawLighthouse.categories['best-practices'].score} \times 100)$
* `categoryScores.seo` = $\text{round}(\text{rawLighthouse.categories.seo.score} \times 100)$

Core Web Vitals metrics are also converted into `AuditCheckResult` checks in the Check Registry:
* **FCP**: First Contentful Paint (`LH_FIRST_CONTENTFUL_PAINT`)
* **LCP**: Largest Contentful Paint (`LH_LARGEST_CONTENTFUL_PAINT`)
* **CLS**: Cumulative Layout Shift (`LH_CUMULATIVE_LAYOUT_SHIFT`)
* **TBT**: Total Blocking Time (`LH_TOTAL_BLOCKING_TIME`)
* **Speed Index**: Visual page load progression (`LH_SPEED_INDEX`)
* **TTI**: Time to Interactive (`LH_INTERACTIVE`)
